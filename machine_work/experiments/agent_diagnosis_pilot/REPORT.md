# Agent 可观测与诊断 pilot：真实执行报告

日期：2026-10-09。结论：**诊断实验可以落地，已有可测量、可审查的研究问题；当前只验证诊断链路，不证明新方法提升或自进化有效。**

使用 Who&When 的 12 个不同任务，Algorithm-Generated / Hand-Crafted 各 6 条，覆盖各自短、中、长轨迹。固定 `gpt-6-astra / xhigh`，比较完整轨迹与 12,000 字符的完整步骤首尾截取基线，每条件独立调用一次，共 24 次真实诊断。

## 实际结果

| 指标 | 完整轨迹 | 首尾截取 |
|---|---:|---:|
| 合法返回（含主动弃权） | 12/12 | 12/12 |
| 责任 Agent 精确命中 | 6/12，50.0% | 5/12，41.7% |
| 错误步骤精确命中 | 4/12，33.3% | 3/12，25.0% |
| Agent 与步骤联合精确命中 | 4/12，33.3% | 3/12，25.0% |
| Agent 命中且步骤误差 ≤1（次要） | 5/12，41.7% | 4/12，33.3% |
| 主动弃权，主要指标计零 | 3/12 | 6/12 |
| 所引证据 ID 均在输入可见范围内 | 12/12 | 12/12 |
| 输入 tokens，含 CLI 上下文 | 197,790 | 96,472 |
| 输出 tokens，服务端报告值 | 10,997 | 8,740 |
| 平均单次耗时，含启动与网络 | 44.8 秒 | 37.8 秒 |

两组累计输入 294,262 tokens（其中缓存输入 21,632，为输入的子集）、输出 19,737 tokens。24 次正式调用以 3 并发运行，墙钟耗时 **337.5 秒**，无传输重试、无格式错误、无工具调用。前期 3 次玩具探针另消耗输入 27,272、输出 373 tokens，不计入上表准确率和正式调用成本。这里记录的是实际 usage，未换算订阅计费金额。

首尾截取使全部 12 条的轨迹字符总量减少 **76.8%**，总输入 tokens 减少 **51.2%**。字符预算只约束 trace，不包括问题、Agent 系统提示和诊断指令；这是字符预算比较，不是 token 配平比较。

## 分组与成对检查

| 分组 | 任务数 | 完整轨迹 joint | 首尾截取 joint | 输入 token 减少 |
|---|---:|---:|---:|---:|
| 实际发生截取 | 8 | 2/8 | 1/8 | 60.9% |
| 轨迹原本就在预算内 | 4 | 2/4 | 2/4 | 约 0% |

4 个未截取任务的两次 prompt 文本及 SHA-256 相同，均由新进程、新会话独立调用；本轮 Agent/步骤联合判分没有变化。这不足以估计模型方差。

12 个成对结果中：两组都正确 2 个、仅完整正确 2 个、仅截取正确 1 个、两组都错误 7 个。截取组保留了标注错误步骤的任务为 8/12；在真正被截取的 8 个任务中仅保留 4/8。不能把未发生截取的 4 个任务视为压缩方法收益。

## 最有价值的现象

**保留错误步骤，不等于保留诊断证据链。** `handcrafted_012` 的标注是 Assistant @16：完整条件正确，引用来源表 @8、@12 和结论 @16。预算条件保留了 @16，却删除了两张来源表。@16 对已经抄错的列表进行交集计算，内部算术自洽；缺少来源时，模型选择弃权。这个案例支持把研究目标具体化为：在有限输入预算内，保留“来源 → 摘录/决策 → 结论”的跨步骤依赖。

**只保留末尾矛盾，可能使定位移向后果。** `handcrafted_031` 完整条件命中 Orchestrator @9；预算条件删掉 @8/@9，仍能发现末尾的地理约束矛盾，但预测 Orchestrator @29，偏移 20 步。选对 Agent 不能替代定位准确。

也有相反的单例：`algorithm_104` 截取正确、完整错误。单次调用不能证明截取去噪有效。`algorithm_106` 则在相同完整输入下均定位到后续核验，未命中标签要求的信息引入步骤。部分低分还涉及轨迹可诊断性与人工归因边界，例如 `handcrafted_021` 的滚动检索、API content-filter 中断及责任标签之间的关系。

以上均为事后个案审查，未改标签或补跑挑选结果。详细原文、可见步骤与预测见 [case_audit.md](results/case_audit.md)。证据引用 ID 合法只代表引用可见，不代表解释正确或因果关系已获证实。

## 可复现性与证据边界

- 官方源固定提交 `f4d2b6da464a826580e59b3a0eae15ea2d642d7c`，184 条轨迹对应 139 个独立 question_ID；本轮抽取 12 个不同任务，未按标签筛选。按来源与长度均衡抽样，不代表数据集自然分布。
- 计划、两组输入、运行顺序和 6 个代码/协议 hash 在正式调用前冻结。24 份输入均经独立重新生成与 hash 核对；删除或修改原始 JSON 顶层答案/诊断注释，不改变任何 prompt。
- 输入包含 question、可选 system_prompt、清洗后的 history 和观测到的 Agent 名称。原始 JSON 读入程序内存时仍有注释字段，字段白名单将其排除；运行器未读取独立 gold.json，评分阶段才使用该文件。
- **官方诊断 prompt 提供任务正确答案，本轮没有提供。** 因此本轮是无答案辅助的诊断改编实验，不能将这里的准确率直接与论文表格比较。未来正式基线应分别固定“有任务答案”与“无任务答案”设置；任务答案也应与责任 Agent/步骤标签明确区分。
- 使用 Agent 规范化后精确相等、原始零基整数步骤精确相等；不用官方 scorer 的 substring 匹配。弃权与格式失败分开，准确率始终保留全部计划任务作分母。原始行动/输出归因边界未临时重标。
- Codex CLI 为固定运行环境，非裸 API；关闭检索、记忆、插件、代码/浏览器等工具，并审核真实事件流。运行时说明仍进入输入，usage 含其开销。配置、版本、命令和原始响应均保留。
- 每任务每条件仅 1 次，N=12 无法给出可靠显著性或方法有效性结论；也未评估正常轨迹误报、跨数据集泛化、自然语言解释质量或真实干预因果效应。

36 项单元测试通过，覆盖字段隔离、完整步骤截取、严格评分、弃权/越界验证、运行审计和固定分母统计。正式调用 24/24 合法、0 工具调用、输入没有显式答案/诊断标签，达成预设的运行可行性门槛；这不等于质量门槛已经达成。

## 下一步实验决策

**值得继续做“诊断所需证据的预算内保留”。** 下一轮应先固定独立任务级开发/测试划分，扩大样本并重复运行；以完整轨迹、首尾截取、其他简单选择基线为对照，验证证据依赖选择能否在相近输入成本下减少根因定位丢失。保留标注错误步骤只能作辅助指标，应增设经过人工核验的支持证据链检查。

**自进化仍需另一个可执行实验。** 本轮 `repair_hint` 只是建议；没有执行修复、更新持久策略/记忆或评估未见任务。Who&When 静态轨迹可支持诊断评价，单独不能验证“诊断 → 持久改进 → 新任务收益”的闭环。
